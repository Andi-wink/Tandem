# F004, F005 & F007 Planning Reference

**Date**: 2026-02-19
**Author**: Planning session with Claude Code
**Purpose**: Reference document for agents implementing F004 (Clipboard Integration), F005 (Presidio PII Anonymization), and F007 (Claude Code Panel). Captures all decisions made, the rationale behind them, and how the features relate.

---

## 1. Project Context

**Tandem** is a privacy-first discovery call assistant — a fork of Meetily (Zackriya-Solutions/meeting-minutes) repurposed for sales discovery calls. It records, transcribes (local Whisper), and summarises meetings. It is a **Tauri 2.x desktop app** (Rust + Next.js 14 + TypeScript) with a **FastAPI Python backend** for meeting persistence and LLM summarisation.

F007 and F005 are specifically about enabling the user to work with an AI coding assistant (Claude Code) **during and after** a discovery call, with PII anonymization so that customer data never leaves the machine unredacted.

F004 captures clipboard content (text or images) during a call so the user can timestamp and persist material they copy from external sources (competitor docs, pricing tables, product specs).

The canonical source of truth for implementation steps is [feature_list.json](../feature_list.json). This document explains the **why** behind those steps.

## 2. F004 — Clipboard Integration (Completed)

### 2.1 What It Is

A global hotkey (Alt+Shift+V) and UI button ("Clip") that captures the current system clipboard — text or image — as a timestamped item in the active meeting timeline. Clips are displayed inline with transcripts and screenshots, persisted to `clipboard.json` in the meeting folder when recording stops, and loaded in the past-meeting details view.

### 2.2 Architecture (Mirrors F002 Screenshot Pattern)

F004 follows the exact same architectural pattern as F002 (Screenshot module). This was deliberate — reusing a proven pattern minimised new design decisions:

- **Rust module**: `frontend/src-tauri/src/clipboard/{mod.rs, types.rs, capture.rs, commands.rs}`
- **arboard v3**: Cross-platform Rust crate for clipboard access. Tries `get_text()` first (non-empty check), then `get_image()`. On Windows, uses WinAPI clipboard APIs directly.
- **Image handling**: `arboard::ImageData` (raw RGBA bytes) → `image::RgbaImage` → saved as PNG in `{meeting_folder}/clipboard/`. Thumbnails generated by reusing `screenshot::capture::generate_thumbnail_from_path()`.
- **Hotkey**: Alt+Shift+V registered in the same plugin builder `.with_handler()` closure as Alt+Shift+S and Alt+Shift+R (see Section 2.4 for the critical registration pattern).
- **Frontend context**: `ClipboardContext` mirrors `ScreenshotContext` exactly. Listens for `clipboard-captured` Tauri event → appends to state. Listens for `recording-stopped` → auto-saves `clipboard.json`.
- **Timeline**: Extended `useTimeline` hook, `TimelineFilterBar`, and `VirtualizedTranscriptView` to render a third item type: `'clipboard'`.

### 2.3 ClipboardData Type

```typescript
export interface ClipboardData {
  id: string;
  content_type: 'text' | 'image';
  text?: string;
  file_path?: string;
  thumbnail_base64?: string;         // base64 JPEG (same as ScreenshotData)
  timestamp: string;                 // wall-clock "HH:MM:SS"
  recording_elapsed_secs?: number;   // seconds since recording started
  width?: number;
  height?: number;
}
```

`content_type === 'image'` clips reuse `ScreenshotThumbnail` in the timeline. `content_type === 'text'` clips render as amber cards with a Clipboard icon and a 2-line text preview.

`TimelineItemType` was extended to `'transcript' | 'screenshot' | 'clipboard'` and `TimelineFilter` to `'all' | 'transcripts' | 'screenshots' | 'clipboard'`. The `TimelineFilterBar` dynamically adds a "Clips" filter button only when `clipboardCount > 0`.

### 2.4 Critical: Hotkey Registration Pattern

The existing codebase registers global shortcuts in a **plugin builder `.with_handler()` closure**, not in the `.setup()` block. All three shortcuts share one closure with `if/else if` branching:

```rust
.plugin(
    tauri_plugin_global_shortcut::Builder::new()
        .with_handler(move |app, shortcut, event| {
            if let ShortcutState::Pressed = event.state() {
                if shortcut == &clipboard_shortcut {
                    // spawn async clipboard capture task
                } else if shortcut == &fullscreen_shortcut {
                    // screenshot fullscreen
                } else if shortcut == &region_shortcut {
                    // screenshot region select
                }
            }
        })
        .build(),
)
```

Using `.on_shortcut()` in `.setup()` does **not** compile — `app_handle` and `ShortcutState` are not in scope there. Any future shortcut additions must use the `.with_handler()` pattern.

### 2.5 Persistence Format

`clipboard.json` saved to the meeting folder on recording stop:

```json
{
  "version": "1.0",
  "items": [
    {
      "id": "uuid-v4",
      "content_type": "text",
      "text": "captured text content",
      "timestamp": "14:25:13",
      "recording_elapsed_secs": 83.4
    },
    {
      "id": "uuid-v4",
      "content_type": "image",
      "file_name": "clip_20260219_142513.png",
      "timestamp": "14:26:01",
      "recording_elapsed_secs": 131.2,
      "width": 1920,
      "height": 1080
    }
  ],
  "total_count": 2
}
```

For image clips, only the `file_name` (relative, not full path) is stored. The full path is reconstructed at load time. Thumbnails are regenerated from the PNG file on load — not stored in JSON. This mirrors the `screenshots.json` pattern exactly.

### 2.6 Issues Encountered During Implementation

**1. Hotkey registration error (compile-time)**
Initial attempt added the clipboard hotkey via `.on_shortcut()` in `.setup()`, causing two compile errors:
```
cannot find value `app_handle` in this scope
use of undeclared type `ShortcutState`
```
Fix: moved to the `.with_handler()` closure pattern described in Section 2.4.

**2. Stale timeline on new recording**
When a new recording started, clipboard items and screenshots from the previous session persisted in the timeline. `clearTranscripts()` was called on recording start but `clearScreenshots()` and `clearClipboard()` were not.
Fix: added both clear calls in all three recording start paths in `useRecordingStart.ts` — manual start, auto-start from sessionStorage, and direct start from sidebar window event.

**3. Silent error on button click**
The "Clip" button called `captureClipboard()` which swallowed all Rust errors with only a `console.error`. If the clipboard was empty or the arboard call failed, the user saw nothing.
Fix: added `toast.error` / `toast.info` feedback in `captureClipboard`, and `toast.success` in the `clipboard-captured` event listener in `ClipboardContext`.

### 2.7 Relation to F007

F007 references `clipboard.json` as one of the files in the meeting folder (Section 3.3 of this document). The current F004 implementation saves clipboard files relative to the current meeting folder when recording is active (via `get_current_meeting_folder()`), falling back to `app_data_dir` when not recording. The path structure is already compatible with F007's proposed layout:

```
{meeting_id}/
├── clipboard.json           ← written by ClipboardContext on recording-stopped
└── clipboard/
    └── clip_*.png           ← image clips saved by capture.rs
```

## 3. F007 — Claude Code Panel

### 3.1 What It Is

A right slide-over panel (420px wide) embedded in the Tauri app that spawns a **Claude Code CLI subprocess** per meeting. The user can build code and workflows while the call is progressing, feeding curated context from the meeting directly into Claude Code.

### 3.2 Why Claude Code CLI (not direct API)

The choice between Option A (direct Claude API chat) and Option B (Claude Code CLI subprocess) was deliberate:

- **Option A** gives a clean chat panel but Claude has no agentic capabilities — it cannot read files, run terminal commands, write code to disk, or make commits. It can only respond with text.
- **Option B** (chosen) gives full Claude Code power: file reading, bash execution, code generation, git operations. The user's stated goal is to **build code and workflows as the meeting is progressing** — this requires real tool use, not just chat.

Option B downsides accepted:
- **PTY complexity on Windows**: Claude Code expects an interactive terminal. Use `--output-format stream-json` flag which gives structured NDJSON output without PTY requirements, making subprocess communication tractable.
- **Output parsing**: `stream-json` gives clean JSON events per line — solves the ANSI/noisy-output problem.
- **Context injection is a conversation message, not system context**: Mitigated by injecting context once at session start via the context basket, and by auto-generating `CLAUDE.md` in the meeting folder (Claude Code reads this automatically as project context).
- **Claude Code must be installed separately**: Accepted. Onboarding must check for `claude --version` on PATH.
- **PII interception**: Claude Code manages its own API calls — you cannot intercept what it sends to Anthropic servers. Mitigation: sanitize the context basket payload (via F005) **before** it is sent to the subprocess. This is the only control point. See Section 4.

### 3.3 The Meeting Folder = Claude Code Project Root

Each meeting gets its own folder on disk. Claude Code is spawned with `cwd` set to that folder, making it the project root.

```
$APPDATA/Tandem/meetings/{meeting_id}/
├── CLAUDE.md                    ← auto-generated; Claude reads this on startup
├── transcript.json              ← mirrored from SQLite at record time
├── screenshots/                 ← moved from flat $APPDATA/screenshots/
│   ├── {timestamp}_{id}.png
│   └── thumbnails/
├── clipboard.json               ← from F004, saved here
├── clipboard/
│   └── clip_*.png               ← image clips from F004
├── notes.md                     ← exported meeting notes
└── .tandem/
    ├── session.json             ← Claude Code session ID + project_dir
    └── entity_map.json          ← PII surrogate registry (F005)
```

**Why this folder structure matters:**
- SQLite stays as the index for fast sidebar listing and search. The meeting folder is the Claude project.
- `CLAUDE.md` is auto-generated by Tandem when the Claude panel is first opened for a meeting. It includes: available files list, meeting title, date, role instructions for Claude. Claude Code reads `CLAUDE.md` from the project root automatically — this gives Claude meeting context without the user having to inject it every message.
- The `.tandem/` subfolder is Tandem-specific metadata invisible to normal file operations.
- **Screenshot paths changed**: F002 saved screenshots to a flat `$APPDATA/screenshots/` directory. F007 Phase 1 moves this to `{meeting_id}/screenshots/`. This is a breaking change that must be coordinated with F002's `capture.rs` save path.

### 3.4 Session Persistence

The user requirement: *"I want to be able to continue the conversation on that project after the call ends."*

Solution: Claude Code CLI supports `--resume <session_id>` to resume a previous conversation. Tandem:
1. On first message to a meeting → spawns `claude --output-format stream-json -p "<message>"` in the meeting folder cwd → captures the session ID from the first NDJSON event.
2. Saves session ID to `{meeting_id}/.tandem/session.json`.
3. On all subsequent messages (same session, or reopening post-call) → `claude --resume <session_id> --output-format stream-json -p "<message>"`.
4. When the meeting panel is reopened, `get_claude_session` checks for existing `session.json` and skips the `ProjectDirModal` if found.

This means the conversation persists indefinitely as long as Claude Code's server-side session is alive — the user can open a meeting from 3 days ago and continue where they left off.

### 3.5 Context Basket

The core UX for feeding meeting content to Claude Code. The basket:
- **Clears after each send** (does not accumulate between messages).
- Can receive items from three sources:
  1. **5-minute transcript chunks** — the timeline is extended to show draggable chunk cards (not just screenshots). Each chunk = a 5-minute window of transcript segments. User drags or clicks to add.
  2. **Text highlight → basket** — `onMouseUp` / `onSelectionChange` listener on transcript container shows a floating `+ Add to Claude` button. Click adds selected text as a `highlight` basket item.
  3. **Manual text note** — typed directly into the basket.
- Screenshot basket items are **not** sent as file paths. Instead they become `[Screenshot at HH:MM — user description]` text descriptions. This prevents Claude Code from reading the image file directly and bypassing PII anonymization (see F005).

On send, basket items are assembled into a formatted context block prepended to the user's message:

```
--- Discovery Call Context (Acme Corp, 2026-02-19) ---
[14:00–14:05 Transcript]
"Customer said they need Salesforce integration..."

[Screenshot at 14:02]
ERD diagram shared by customer

[Highlighted] "They mentioned a $50k budget ceiling"
---------------------------------------------------------

[User's actual message to Claude]
```

This block is the **only thing that passes through F005 PII anonymization** before reaching the subprocess.

### 3.6 Project Directory Modal

Shown the first time the Claude Panel is opened for a meeting (when no `session.json` exists).

Two options:
1. **Meeting folder** (default): Claude Code spawns in `{meeting_id}/`. CLAUDE.md, transcript.json, and screenshots are all directly accessible to Claude Code as files.
2. **Existing project repo**: User browses to a local repo path via Tauri `dialog::open`. Claude Code spawns there. Meeting artifacts are still in the Tandem folder but referenced by path if needed.

The chosen directory is saved in `session.json` alongside the session ID.

### 3.7 Tool Use Display

Claude Code's tool calls (file reads, bash, file writes) render in the conversation as **collapsible blocks**:
- Collapsed: `▶ Reading file: transcript.json`
- Expanded: full file content / bash output / diff

This mirrors the VS Code Claude Code panel's UX which the user wanted to emulate.

### 3.8 Layout

- Right slide-over panel, 420px wide.
- When open, `MainContent/index.tsx` adds `mr-[420px]` (mirrors the left sidebar `ml-64` pattern).
- Toggle button anchored to the right edge of the main content, using `Bot` icon from lucide-react.
- Panel available on both `app/page.tsx` (live recording) and `app/meeting-details/page.tsx` (post-call review).

### 3.9 Rust Architecture

New module `frontend/src-tauri/src/claude/`:
- `types.rs`: `ClaudeSessionState`, `ClaudeStreamEvent` enum (parsed from stream-json NDJSON).
- `session.rs`: `spawn_first_message()`, `send_message()`, `generate_claude_md()`, `save_session_json()`, `load_session_json()`.
- `commands.rs`: 4 Tauri commands — `start_claude_session`, `send_claude_message`, `get_claude_session`, `clear_claude_session`.

No new Cargo dependencies — shells out to the `claude` CLI via `std::process::Command`. The subprocess pipes stdout line-by-line; each line is a JSON event emitted as a Tauri event to the frontend.

**Critical implementation note**: Test `claude --output-format stream-json -p "hello"` manually before writing the Rust parser. The session ID field name and event schema must be confirmed from actual CLI output, not assumed.

## 4. F005 — Presidio PII Anonymization Pipeline

### 4.1 What It Is

On-device PII anonymization integrated into the existing FastAPI Python backend. Anonymization happens **at send-time** (when the user hits Send in the Claude Panel), not at storage time. The raw transcript in SQLite and `transcript.json` is always stored unmodified.

### 4.2 Why Presidio (not n8n)

Original F005 spec used n8n as an external workflow engine. This was replaced with **Microsoft Presidio** running directly in the FastAPI backend because:
- Presidio is a Python library — installs directly into the existing backend, zero new infrastructure.
- No network hop, no separate process to manage, no failure mode if n8n is down.
- Fully offline — aligns with Tandem's privacy-first positioning.
- n8n would have added operational complexity (separate service, port management, another thing to start) with no benefit over Presidio.

Reference: [theaiautomators/claude-code-agentic-rag-series ep3 PRD](https://github.com/theaiautomators/claude-code-agentic-rag-series/tree/main/ep3-redaction-anonymization-video) — a detailed PRD (no code yet) for a Presidio-based anonymization system. The techniques described there directly informed this design.

### 4.3 Two-Tier Detection Strategy

The key insight from the reference PRD: **different types of PII warrant different confidence thresholds**.

| Tier | Entity Types | Threshold | Action | Rationale |
|---|---|---|---|---|
| **Surrogate** | PERSON, EMAIL, PHONE, LOCATION, DATE_TIME, URL, IP_ADDRESS | **0.7 (high)** | Replace with realistic Faker alias | False positive = harmless fake name. High threshold prevents spurious replacements that would confuse Claude mid-session. |
| **Hard redact** | CREDIT_CARD, US_SSN, US_ITIN, US_BANK_NUMBER, IBAN_CODE, CRYPTO, US_PASSPORT, US_DRIVER_LICENSE, MEDICAL_LICENSE | **0.3 (low)** | Replace with `[TYPE]` placeholder | False positive = harmless placeholder. False **negative** = real SSN reaches Anthropic servers. Low threshold intentionally aggressive. |

### 4.4 Entity Registry = Per-Meeting Alias Map

The most important design decision for usability: **consistent pseudonymization within a session**.

Simple redaction (`[REDACTED]`) destroys Claude's ability to reason about relationships ("what did the CTO want?"). Instead, each unique real entity maps to a stable alias for the entire meeting session:

```json
{
  "John Smith":       "Marcus Webb",
  "Sarah Johnson":    "Claire Park",
  "Acme Corp":        "Company A",
  "john@acme.com":    "marcus@company-a.com",
  "+44 7911 123456":  "[PHONE-1]"
}
```

The map is stored in `{meeting_id}/.tandem/entity_map.json` (the `.tandem/` folder established by F007 Phase 1). New entities discovered in later basket sends are merged into the same map. The map accumulates throughout the meeting session and all post-call continuations.

### 4.5 Name Clustering (Union-Find)

The hard problem: "John", "Mr. Smith", "John Smith", and "Johnny" all refer to the same person and must all map to the same surrogate alias.

Implementation uses a Union-Find algorithm with:
- `nameparser` library to split names into components (title, first, middle, last, suffix).
- A nickname dictionary to resolve diminutives: "Johnny" → "John", "Danny" → "Daniel".
- Three merge rules: (1) same canonical first + last → merge; (2) lone last name → merge if exactly one cluster has that last name; (3) lone first name → merge if exactly one cluster has that canonical first name.
- **Sub-surrogate derivation**: if "John Smith" → "Marcus Webb", then "Mr. Smith" → "Mr. Webb", "Johnny" → "Marcus" automatically.

### 4.6 UUID False-Positive Filter

Meeting IDs and document reference IDs in Tandem are UUIDs (e.g., `d301a04a-9ca5-4e92-b8a3-40a769d6ceac`). Presidio's PERSON/LOCATION recognisers can falsely detect hex substrings within UUIDs. A regex filter excludes UUID-pattern matches from Presidio results before anonymization runs, preventing document IDs from being corrupted.

### 4.7 What Is NOT Anonymized

- **`transcript.json`** on disk — always raw, always real. Storage-time anonymization causes double-anonymization problems (Faker surrogates are realistic names that Presidio re-detects on a second pass, creating a cascade of false aliases).
- **SQLite meeting database** — always raw.
- **Screenshot image files** — cannot be text-anonymized. Instead, screenshot basket items are converted to text descriptions before the context block is assembled, so the image file path is never sent to Claude Code (Claude Code would otherwise read the raw image directly). User optionally adds a text description of the screenshot; that text goes through Presidio.
- **Clipboard image clips** — same constraint as screenshots. Clipboard image basket items must be converted to text descriptions before anonymization, following the same pattern as screenshot basket items.
- **Claude Code's own tool outputs** — once the context block is sent to the subprocess, Claude Code makes its own file reads and bash executions. Those results go back to Claude's API directly and are not interceptable. This is a known limitation documented in F007's conflict notes.

### 4.8 De-anonymization: V2 Only

The reference PRD describes a sophisticated three-phase placeholder pipeline for reversing surrogates in LLM responses (replacing fake names with real names before displaying to the user). This is **not implemented in F005 V1**. Rationale:
- Claude Code's output (specs, code, files) uses fake names — this is acceptable because the user knows the entity map.
- The `EntityMapViewer` component in the Claude Panel shows the Real → Alias table, so the user can always look up who "Marcus" is.
- The three-phase pipeline solves a subtle surname-collision bug (where a fuzzy de-anonymization pass corrupts real names by partial matching surrogate components) — it is complex and not needed until de-anonymization is a priority.

### 4.9 Backend Implementation

New file: `backend/app/anonymizer.py`

New FastAPI endpoints in `backend/app/main.py`:
- `POST /api/anonymize` — main endpoint; accepts `{ text, entity_map, meeting_id }`; returns `{ sanitized, entity_map, entities_found }`.
- `GET /api/anonymize/entity-map/{meeting_id}` — returns current map for UI display.
- `DELETE /api/anonymize/entity-map/{meeting_id}` — clears the map.

New Python dependencies in `backend/requirements.txt`:
```
presidio-analyzer
presidio-anonymizer
spacy
faker
nameparser
gender-guesser
```

Requires: `python -m spacy download en_core_web_trf` (~500MB) — must be part of backend setup/onboarding.

### 4.10 Frontend Integration Point

`services/anonymizationService.ts` — REST client to the FastAPI anonymize endpoints.

In `contexts/ClaudeContext.tsx`, the `sendMessage()` action:
1. Assembles the context basket into a raw text block.
2. If sanitization toggle is on → calls `anonymizationService.anonymizeText(rawBlock, meetingId)`.
3. Passes the returned sanitized text (or raw text if toggle is off) to `claudeService.sendMessage()`.
4. Updates `entityMap` state in context (drives `EntityMapViewer`).

The **sanitization toggle** is per-meeting, persisted to `.tandem/session.json`, shown as a shield icon in the ClaudePanel header (green = sanitizing, grey = off).

## 7. Key Risks and Things to Verify Before Coding

### F007 Risks

1. **stream-json event schema**: Run `claude --output-format stream-json -p "hello"` manually and inspect the NDJSON output before writing the Rust parser. Specifically: what is the field name for the session ID? Is it in the first event or a separate init event? What are the event type values?

2. **`--resume` flag behaviour**: Verify `claude --resume <id> --output-format stream-json -p "message"` works as expected. Confirm what happens when the session ID is stale/expired.

3. **Windows PATH**: `std::process::Command::new("claude")` on Windows requires `claude.exe` or `claude.cmd` to be on the system PATH. Test that Tauri's subprocess environment inherits the user's PATH correctly — it may need explicit PATH injection from the Tauri app's environment.

4. **cwd and CLAUDE.md**: Verify that spawning `claude` with a `cwd` pointing to the meeting folder causes it to pick up `CLAUDE.md` from that folder. This is the core assumption behind the auto-context approach.

### F005 Risks

1. **spaCy model size**: `en_core_web_trf` is ~500MB. This needs to be a clear step in the backend setup script. Consider whether a smaller model (`en_core_web_sm`, ~15MB) is acceptable for V1 with lower NER accuracy on names.

2. **Anonymization latency**: First request after backend startup will be slow (spaCy loads transformer model). Subsequent requests are fast (model cached in memory). The backend should pre-warm the model at startup, not on first request.

3. **Faker surrogate collision with Presidio re-detection**: The PRD notes this explicitly — Faker generates realistic names that Presidio will re-detect as PERSON entities on a second pass. This is why anonymization must happen at send-time only, never on stored transcripts. The `anonymize()` function must not be called multiple times on the same text.

4. **Gender-guesser accuracy**: The library guesses gender from first names for gender-matched surrogate generation. It may be wrong or return `unknown` for ambiguous names. Fall back to random gender when `unknown`.

### F004 Known Issues (for future agents)

1. **arboard on Windows in certain contexts**: The `captureClipboard` button may silently fail if the clipboard is empty or holds a format arboard cannot read. Toast feedback has been added to surface errors — if users report "nothing happens", check the toast message to diagnose the Rust-side error.

2. **Clipboard image + PII (F005 dependency)**: When F005 is implemented, clipboard image clips in the context basket must be treated the same as screenshot basket items — converted to text descriptions, not sent as file paths. The image file in `{meeting_id}/clipboard/` would otherwise be read directly by Claude Code, bypassing anonymization.
